# Подготовка выпуска Windows x64

Проверенное окружение: **CPython 3.12.10**, Windows 10/11 x64. Номер версии задаётся один раз в `core/version.py`. Для текущих изменений подготовлена версия **1.1.1**.

## Сборка

```powershell
py -3.12 -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\venv\Scripts\python.exe scripts/prepare_tools.py
.\venv\Scripts\python.exe tests/run_tests.py
.\venv\Scripts\python.exe build_exe.py --download-tools
```

Сборка проверяет версии всех зависимостей и наличие лицензий. FFmpeg/FFprobe скачиваются из фиксированного архива Gyan с проверкой SHA-256 из `packaging/tools.json`. Дистрибутив содержит FFmpeg, FFprobe, Deno и EJS-компоненты yt-dlp; Python и системный FFmpeg конечному пользователю не нужны. Приложение запускается без прав администратора.

Выходные файлы:

- `dist/AuraDownloader/AuraDownloader.exe` — программа; сохраняйте рядом всю папку `_internal/`.
- `dist/AuraDownloader-v1.1.1-windows-x64.zip` — переносимый дистрибутив.
- `dist/AuraDownloader-v1.1.1-windows-x64.zip.sha256` — контрольная сумма архива.
- `dist/smoke-report.json` — результаты проверки готового EXE.
- `dist/AuraDownloader/build-manifest.json` — версии, ревизия исходников и контрольные суммы FFmpeg/FFprobe.

Режим `--onefile` также поддерживается, но требует распаковки компонентов при каждом старте. Основной проверяемый дистрибутив — папка приложения.

## Проверки готового EXE

Перед созданием архива сборка переносит приложение в каталог с русскими буквами и пробелами, запускает его из другой рабочей папки, очищает PATH от Python/FFmpeg/Deno и создаёт отдельный профиль. Проверяются запуск Qt, значок, главное окно и настройки, метаданные и превью, реальная нарезка/масштабирование/OPUS/GIF, сохранность исходника, запись настроек/истории/журнала и закрытие с активной фоновой задачей. Проверка не читает cookies браузера и не обращается к онлайн-сервисам.

Повторная проверка:

```powershell
.\venv\Scripts\python.exe scripts/check_packaged_app.py dist/AuraDownloader/AuraDownloader.exe
```

GitHub Actions повторяет тесты, сборку и проверку EXE на новом runner Windows. Вкладка Actions содержит архив, SHA-256 и отчёт. Workflow имеет только права чтения репозитория и не публикует релизы автоматически.

Перед публичным стабильным релизом дополнительно выполните ручные сценарии:

1. На Windows 10 и 11 без установленного Python распакуйте архив, запустите EXE двойным кликом и откройте настройки; проверьте масштаб экрана 100/150/200% и узкое окно.
2. Загрузите общедоступное видео YouTube со звуком, плейлист, прямую ссылку и галерею; отдельно проверьте необходимые вам сервисы и cookies своего браузера. Доступность сайтов меняется и не доказывается офлайн-проверкой.
3. Отмените загрузку, повторите сбои, закройте окно во время обработки. Проверьте исходники и готовые результаты.
4. На совместимом GPU проверьте реальную RIFE-интерполяцию, длительность и звук. Автоматические тесты не оценивают качество нейросети или драйвер Vulkan.
5. Проверьте SHA-256, состав `licenses/` и исходники распространяемых компонентов. Для подписанного выпуска подпишите EXE своим сертификатом и проверьте подпись. Эта сборка не подписана.

## Обновления и журнал

В EXE кнопка **Проверить обновления** обращается к стабильным релизам `csezet/aura-downloader` и предлагает открыть их страницу при наличии новой Windows-сборки. Сам EXE не запускает pip и не заменяет файлы работающей программы. Для установки обновления закройте приложение и распакуйте новый архив в другую папку: настройки и история останутся в профиле пользователя.

В исходниках кнопка **Обновить yt-dlp** обновляет пакет вместе с Deno/EJS; после этого требуется перезапуск. Выпуск обновлённой EXE-сборки выполняется через повторную сборку с обновлённым lock-файлом.

Кнопка **Журнал ошибок** открывает `%LOCALAPPDATA%/AuraDownloader/logs/`. Для каждого процесса используется отдельный файл с ротацией (2 МБ и три резервных файла). Журнал содержит ошибки фоновых задач, Qt и неперехваченные исключения; URL и явные поля авторизации маскируются. В нём могут оставаться локальные пути, поэтому просматривайте файл перед отправкой.
